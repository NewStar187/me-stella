# Gate 1 기획서 — §0 재베이스라인 (초안 v0.1, 2026-08-29)

선언: 로드맵 v2.0 리스크 R6의 "범위 조정은 게이트에서만" — 본 절로써 Gate 1이 범위 조정 게이트를
겸한다. 입력: M2 잔여 공수표(08-28 산정), 시나리오 B, 컷 우선순위(08-29 확정).

## 0.1 확정 입력값 (Q-a)
- M2 잔여 공수: 중심 20 작업일 / 상한 31.5 작업일
  (행별 3점 추정 × 경험 계수 웹 1.5 · Unity 2.0)
- 주당 가용: 5일 = 개발 3일 + 기획·문서·콘텐츠 2일
- 독립 추정 2개(공수표 · 인수인계 캘린더 대조) 수렴 확인

## 0.2 컷 발동 (Q-c) — 우선순위 ①→②→④→③, 산술상 전부 발동
- C1  Stage 6 → v1.1 이월. v1.0 콘텐츠 = Stage 4~5, 240문제
      (Gate 2 공식 축소 플랜 발동)
- C2  게임화 구현(M4) 4주 → 2주 목표. 정확 범위는 본 기획서 공수 산정에서
      확정. 최소 게임 루프(지도→플레이→완료 연출)는 이월 불가 (로드맵 원칙)
- C3  카카오 OAuth → v1.1 이월 (v1.0은 이메일+구글). 0.75일 절약 +
      비즈앱 심사 대기라는 달력 리스크 제거
- C4  진단 퀵체크 제외 (원 로드맵 "여유 시" 항목 — 계획에서 삭제)
- 부속: 온보딩 = 1일 예산제 (화면 구성은 예산 내에서 기획)

  M5+M6 통합 4주(11/26~12/23, 클로즈드 베타 2주 = 11/30~12/13 사수)

- 잔차 리스크: QA·출시 8주→4주 압축은 고위험. 흡수 후보 2안을 Gate 1

  ㄱ) Gate 1 종결 후 개발일 3→4 상향(콘텐츠 1일) — 실측 속도가
      "주 30문제를 주 1일로" 감당할 때만 성립
