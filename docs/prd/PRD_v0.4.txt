1. 제품 개요 (Product Overview)
────────────────────────────────────────────────────────────────────────────────

1.1 서비스명 (가칭)
    Me.Stella  (정식 명칭 미정 — OQ-02)

1.2 한 문장 정의
    한국 공식 수학과 교육과정(초등 1학년 ~ 고등 미적분Ⅰ)을 게임 방식으로
    재해석한 브라우저 기반 수학 학습 서비스. 게임 화면은 Unity(Web)로,
    텍스트 중심 화면과 서버는 웹 기술로 구현하며, 설치 없이 링크 하나로
    접근 가능하다.
    ※ 게임 메카닉·세계관의 구체 내용은 섹션 10(현재 공백) 확정 후 반영.

1.3 배경 및 기회
    국내 수학 에듀테크(콴다·매쓰플랫 등)는 문제 풀이 도구 중심이며,
    개념 이해의 재미를 제공하는 서비스는 사실상 부재하다. 해외의
    Prodigy Math는 초·중등 수학 게임으로 대규모 사용자를 확보했으나
    한국 교육과정 미연동·고등 수학 부재라는 공백이 있다.
    교육부 고시 제2022-33호 [별책 8] 수학과 교육과정 전 범위(초1~미적분Ⅰ)를
    커버하는 게임형 학습 서비스는 국내외에 존재하지 않는다 — 이것이
    본 프로젝트의 핵심 차별점이자 방어선이다.
    Unity 채택의 전략적 의미: v1(브라우저) 이후 동일 코드베이스로
    iOS/Android 네이티브 앱(v2)으로 확장할 수 있는 자산이 된다.

1.4 목표
    - Month 6      : v1.0 출시 (Stage 4~6 콘텐츠 100%, Critical 버그 0)
    - 출시 +1개월  : 누적 가입 300명, WAU 100명
    - 출시 +3개월  : 누적 가입 1,000명, MAU 400명, Stage 7 콘텐츠 릴리즈
    - 학습 목표    : 서비스 내 측정 가능한 대리 지표로 정의 (섹션 15.3)

1.5 범위 원칙 (6개월 · 1인 개발 · Unity 신규 도입)
    - 모든 요구사항은 "1인이 6개월 안에 만들 수 있는가"로 재단한다.
    - Unity는 이번 프로젝트에서 처음 도입하는 기술이다. 따라서
      ① 2D 한정 ② 외부 에셋 최소 ③ Gate 0에서 조기 검증 ④ 실패 시
      회귀 경로 보유 — 이 네 가지를 아키텍처 원칙으로 못 박는다.
    - 범위에 없는 좋은 아이디어는 백로그로 보내며, 범위 조정은
      로드맵의 게이트에서만 한다.

2. 문제 정의 (Problem Statement)
────────────────────────────────────────────────────────────────────────────────

2.1 핵심 고통 포인트

    [학생 관점]
    P1. 수학이 왜 필요한지 체감하지 못한 채 암기식으로 공부한다.
    P2. 혼자 개념 이해에 실패하면 포기하는 수포자 현상이 발생한다.
    P3. 유튜브·게임 대비 수학 학습은 즉각적 보상이 없어 지속이 어렵다.
    P4. 학원·과외 없이 스스로 학습할 수 있는 재미있는 도구가 없다.

    [학부모·교사 관점]
    P5. 자녀/학생이 어느 개념에서 막혀 있는지 파악하기 어렵다.
    P6. 수학 학습 시간을 늘리도록 유도할 내재적 동기 수단이 부족하다.

2.2 기존 해결책의 한계
    - 콴다      : 답 제시가 목적 → 개념 이해 없이 베끼기 유도
    - 매쓰플랫  : B2B 학원 문제은행 → 학생 직접 사용성 낮음
    - Prodigy   : 한국 교육과정 미연동, 고등 수학 없음
    - 인강(EBS) : 수동적 시청 → 참여도 낮음

3. 타겟 사용자 (Target Users)
────────────────────────────────────────────────────────────────────────────────

3.1 메인 타겟
    초등학교 4학년 ~ 고등학교 2학년 (만 10~17세)

3.2 v1 집중 타겟 (가설 — 사용자 인터뷰로 검증, W4 확정)
    중학생 (Stage 4~6).
    근거: ① 수포자 발생이 집중되는 구간 ② v1 콘텐츠 범위와 정합
          ③ 학교 진도 정렬 가치가 가장 큰 연령대.

3.3 기기 현실 (Unity 전환에 따른 신규 항목)
    학생층의 주 접속 기기는 모바일일 가능성이 높다. Unity 6의 Web
    플랫폼은 일부 모바일 브라우저를 공식 지원하지만, 기기 성능·메모리에
    따라 편차가 크다. 따라서:
    - 사용자 인터뷰에 "주 사용 기기·PC 접근성" 문항을 필수 포함한다 (W2)
    - Gate 0에서 실기기 3종(최신 iOS / 최신 Android / 중급 Android)으로
      구동·로딩을 실측한다
    - v1 공식 지원 기준선은 실측 후 확정한다 (OQ-06)

3.4 페르소나
    [페르소나 1 — 초등 고학년 이준혁, 12세] 게임 친화, 학원 없이 독학.
      니즈: "수학이 게임처럼 재밌으면 할 텐데"
    [페르소나 2 — 중학생 김서연, 14세] ← v1 핵심.
      함수에서 막힘, 질문 수치심. 니즈: "친절한 설명 + 작은 성공 경험"
    [페르소나 3 — 고등학생 박민준, 16세] 유형 암기 한계.
      니즈: "왜 이 공식이 나왔는지 이해하고 싶다"
      v1 시점 콘텐츠 미제공 → v1.1~v1.3 릴리즈로 유입 (출시 안내에
      콘텐츠 범위 명시 — 기대 관리)

3.5 보조 타겟
    학부모(진도·약점 파악), 교사(수업 보조) — v2

4. 학습 체계 (Learning System)
────────────────────────────────────────────────────────────────────────────────

4.1 단일 기준 문서 (SSOT)
    학습 단원의 구조·명칭·학습 목표·성취기준은
    「Me.Stella 커리큘럼 v0.2」 문서를 유일한 기준으로 한다.
    두 문서가 어긋나면 커리큘럼 문서가 우선하고 PRD를 수정한다.

4.2 구조 요약 (10 Stage / 72 Unit)

    Stage  1  초등 1~2학년군      6단원   U01~U06
    Stage  2  초등 3~4학년군      8단원   U07~U14
    Stage  3  초등 5~6학년군      9단원   U15~U23
    Stage  4  중학교 1학년        8단원   U24~U31   ┐
    Stage  5  중학교 2학년        9단원   U32~U40   │ v1.0 콘텐츠 범위
    Stage  6  중학교 3학년        7단원   U41~U47   ┘
    Stage  7  공통수학1           7단원   U48~U54   v1.1
    Stage  8  공통수학2           6단원   U55~U60   v1.2
    Stage  9  대수                6단원   U61~U66   v1.3~
    Stage 10  미적분Ⅰ            6단원   U67~U72   v1.3~
    Stage 1~3 (초등)                                기초 백필 — 우선순위 최하

    ※ 스테이지 테마명(세계관 연동 명칭)은 게임화 기획 확정 후 별도 매핑.

4.3 학년 기반 진입점
    온보딩에서 학년 선택 → 매핑 스테이지 "이하 전체" 개방.
    개방 범위 내 단원은 자유 선택(학교 진도 따라잡기 지원),
    상위 스테이지는 직전 스테이지 전 단원 완료 시 해제.

      초1~2 → Stage 1     초3~4 → Stage 2     초5~6 → Stage 3
      중1   → Stage 4     중2   → Stage 5     중3   → Stage 6
      고1   → Stage 8     고2   → Stage 9     고3   → Stage 10

    선택형 진단 퀵체크(F-14, Should)는 개방 범위 내 선수 단원에
    "복습 권장" 표시를 부여한다. 강제 잠금이 아니다.

4.4 마스터리 판정 (단일 정의 — 서버에서만 계산)
    - 단원 점수: 0~100, 초기값 0
    - 정답 가점: 힌트 미사용 +20 / 힌트1 +16 / 힌트2 +10 / 힌트3 +5
    - 오답 감점: -10 (하한 0)
    - 85점 도달 시 단원 완료(done)
    - Unity 클라이언트는 판정 결과를 표시만 하며 계산하지 않는다 (8.4)
    (수치는 제안값 — 클로즈드 베타 데이터로 조정, 조정 시 CHANGELOG 기록)
    ※ 분류 근거: 마스터리·간격 반복은 학습 과학 원칙(마스터리 러닝,
       간격 반복)의 구현이므로 게임화 공백 처리 대상에서 제외.

4.5 간격 반복 복습 (F-13, Should)
    단원 완료 시 오답·저점수 문제를 복습 큐 등록.
    간격 3일 → 7일 → 21일 (통과 시 다음 간격, 실패 시 3일 리셋).
    "오늘의 복습"에서 일 단위 제시.

4.6 힌트 시스템 (3단계)
    힌트 1 방향 제시 / 힌트 2 첫 단계 제시 / 힌트 3 거의 완성 단계 제시.
    마스터리 반영은 4.4. 보상 연동 여부는 게임화 기획 확정 후 결정.

5. 기능 요구사항 (Functional Requirements)
────────────────────────────────────────────────────────────────────────────────

  ※ 각 기능의 구현 위치(Unity/웹)는 7.2 화면 분담표를 따른다.

5.1 Must Have (v1.0 출시 필수)

    [F-01] 회원 인증 (웹 셸 — Supabase Auth 관리형)
    - 이메일 가입/로그인(인증 메일), 비밀번호 재설정, Google·Kakao 소셜
    - 세션·토큰 관리는 Supabase Auth SDK에 위임 (자체 구현 금지)
    - 로그인 후 Unity 구동 시 JWT를 JS 브릿지로 전달 (7.3)
    - 계정 탈퇴 및 데이터 삭제

    [F-02] 온보딩 (웹 셸)
    - 학년 선택 → 진입 스테이지 개방 (4.3)
    - 시작 단원 추천, 첫 5문제 낮은 난이도 구성 (첫 성공 경험)

    [F-03] 학습 지도 (Unity)
    - 10 Stage 구조의 시각적 학습 경로 (게임 맵)
    - 단원 상태: 잠금 / 학습 가능 / 복습 권장 / 완료 + 스테이지 진도율
    - 단원 선택 시 학습 목표 요약·예상 소요 시간 표시
    - 콘텐츠 미공개 스테이지는 "준비 중" 표기
    - 맵의 시각 테마는 게임화 기획(섹션 10) 확정 후 반영 —
      확정 전까지는 무테마 플레이스홀더 그래픽으로 개발

    [F-04] 개념 학습 페이지 (웹 셸)
    - 단원별 핵심 개념 설명 (KaTeX 수식 렌더링)
    - 예시 워크스루 1~2개, 핵심 정리 카드, 북마크
    - Unity 지도에서 "개념 보기" 선택 시 웹 페이지로 전환 (7.3 라우팅)

    [F-05] 문제 풀이 플레이 (Unity)
    - 문제 유형: 객관식 4지선다, 단답형 (v1은 2종만)
    - 수식은 사전 렌더링된 이미지 에셋으로 표시 (9.5)
    - 단답형 입력: HTML 오버레이 입력 필드 표준 —
      Unity WebGL 내장 입력의 한글 IME 불안정을 회피하는 확정 방식.
      Gate 0에서 모바일 가상 키보드 동작까지 검증한다.
    - 제출 → 서버 채점 → 정오 피드백 (P75 1초 이내), 3단계 힌트
    - 오답 시 관련 개념 카드 연결 (웹 페이지 링크)
    - 정답·해설은 제출 후 응답에만 포함 (8.4)

    [F-06] 마스터리 시스템 (서버 계산 + Unity 표시)
    - 판정 규칙 4.4. 단원 완료 시 다음 단원 해제.

    [F-07] 학습 진도 저장·대시보드 (서버 + 웹 셸)
    - 전 기록 서버 저장, 기기 변경 후 유지

7.5 AI 협업 규약 (Claude Code)
    ① 레포 루트에 CLAUDE.md 유지: 아키텍처 결정(7.1~7.3), 코딩 컨벤션,
       금지 사항(정답 클라이언트 노출, 클라이언트 판정 로직 등)을 명문화.
       Claude Code의 모든 작업은 이 문서를 전제로 한다.
    ② 게이트 동일 적용: AI가 생성한 코드도 셀프 리뷰 + 테스트 통과 후
       머지. 이해하지 못한 코드는 머지하지 않는다 — 이해 못 한 코드는
       기술 부채가 아니라 폭탄이다.
    ③ 권한 경계: 시크릿(.env)·프로덕션 DB 접근 금지. 마이그레이션·시드
       실행은 사람이 명시적으로 승인·실행한다.
    ④ 분업 기준: C# 스크립트·웹 코드·파이프라인 스크립트·테스트 작성은
       Claude Code 적극 활용. Unity 씬·프리팹(YAML) 구조 변경과 에디터
       조작은 사람이 담당 — 씬 파일은 병합 충돌·파손 위험이 높다.
    ⑤ 커밋 소분: 기능 단위 작은 커밋. 대량 생성 후 일괄 커밋 금지.

    - AI 초안 활용 가능. 최종 수치·풀이·범위 조건(U44 "제한된 범위" 등)은
      사람이 검수·서명.

9.3 검수 프로세스
    1) 작성자 셀프 체크리스트 (수치 재계산·성취기준 범위·오타)
    2) 외부 검수자 1인 확인 (R4)
    3) 운영 중 오류 신고(F-12) 24시간 내 비활성화/수정
    출시 게이트: 360문제 전량 1)·2) 통과 + Unity 화면 렌더링 확인.

9.4 성취기준 근거
    topics.achievement_codes / problems.achievement_code에 코드 기입.
    절차는 커리큘럼 v0.2 부록 A.

9.5 수식 사전 렌더링 파이프라인 (신규 — Unity 대응의 핵심)
    - 원고 JSON의 LaTeX 수식을 빌드 타임에 이미지(투명 배경, @2x)로
      일괄 렌더링하는 스크립트를 파이프라인에 포함한다.
    - 산출 이미지는 Supabase Storage에 업로드, URL을 problems 레코드에
      기록 (8.2). Unity는 이미지를 로드해 표시만 한다.
    - 장점: Unity 런타임에 수식 엔진이 필요 없다. 웹(KaTeX)과 원고를
      공유한다. 오탈자 수정 시 재렌더링은 스크립트 1회 실행.
    - Gate 0 검증 항목: 이미지 선명도(저·고해상도 화면), 로딩 지연,
      단원당 이미지 수량이 Storage 1GB 예산 내인지 산정.

10. 게임화 설계 (Gamification Design)
────────────────────────────────────────────────────────────────────────────────

  ⚠ 본 섹션은 의도적으로 비어 있다.
    게임 메카닉·세계관·보상 설계는 기획자(허준성)가 직접 작성하며,
    멘토는 본 섹션의 내용을 제안하지 않는다.

    작성 기한 : W6 (Month 2 중순)
    중요도    : v0.3 대비 상향 — Unity를 채택한 이유가 본 섹션이다.
                기획 없이 Unity로 만드는 것은 무거운 엔진으로 웹 폼을
                만드는 일이 된다.
    지연 시   : R2 절차 — W6까지 최소한 "최소 게임 루프"(지도 이동 →
                문제 플레이 → 완료 연출의 뼈대)는 반드시 정의한다.
                세계관·보상·도전과제는 v1.1 이월 가능, 최소 루프는 불가.
                출시일 연기는 선택지에 없다.

  10.1 보상 시스템                                        [ 미작성 ]
       정의 항목: 보상 단위 / 획득 조건 / 소비처 / 상한·인플레 관리 /
       힌트 연동 / 어뷰징 방지
  10.2 성장 구조                                          [ 미작성 ]
       정의 항목: 성장 축 / 구간 설계 / 진척 표시 위치 / 마스터리(4.4) 관계
  10.3 도전과제                                           [ 미작성 ]
       정의 항목: 유형 / 개수 / 달성 조건의 데이터 정의 / 노출 위치
  10.4 세계관 · 스토리 · 캐릭터                           [ 미작성 ]
       정의 항목: 컨셉 / 10개 스테이지 테마명 / 주인공·NPC /
       진행-스토리 연결 / 텍스트 분량. ※ 10 Stage 전제로 설계할 것.
  10.5 연출 (애니메이션 · 사운드)                         [ 미작성 ]
       정의 항목: 정오답·완료 연출 수위 / 효과음 목록 / 음소거 설정
       (기존 결정: 효과음 > BGM 우선순위, BGM은 v2)

  ※ 확정 시 갱신 지점: 5.3(F-G1~G5), 8.1 게임화 테이블, 11 스토리,
     12 API, 13.5 로드맵 M4 산정, 커리큘럼 스테이지 테마 매핑,
     Unity 에셋 제작 목록.

  US-09 학생으로서, 문제 오류를 알리고 싶다.

    수익화 개시 = 인프라 유료 전환 트리거 (7.6).

14.3 원칙: 광고 없는 학습 환경 / 학습 능력 직결 기능의 유료화는 신중히.
