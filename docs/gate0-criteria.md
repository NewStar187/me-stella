## 부록 — B-1 기준값 3초 사후 대조 (2026-08-28 기록)

※ 사후 기록임. 판정 기준값은 R8에 따라 변경하지 않는다.

1. 사전 등록 시점에 3초의 근거는 문서화되지 않았음.
2. 사후 대조 결과, 3초는 웹 콘텐츠 페이지 기준에서 유래한 값으로 판단됨.
   - Core Web Vitals LCP: 2.5초 good / 4.0초 poor (실사용자 75분위)
   - Google 2016 모바일 이탈 연구: 3초 초과 시 방문 53% 이탈
3. Unity WebGL 애플리케이션 부팅에는 층이 맞지 않음.
   - 커뮤니티 실측: 빈 씬(빌드 3MB) 데스크톱 1.5~3초, 모바일 5~6초
   - 본 프로젝트 빌드 예산 25MB(압축) 기준, 콘텐츠 탑재 후 3초는 달성 불가로 추정
4. 층위 정리 (roadmap-errata.md E-01과 동일):
   - 개발흐름 v2.0의 15초 = No-Go 임계 (아키텍처 회귀 트리거)
   - 본 문서의 3초 = 품질 목표 (Cond.Go 임계)
5. 차기 재측정 시 측정 정의를 3분할하여 사전 등록한다:
   (a) 콜드 캐시 / 웜 캐시
   (b) 웹 셸 로딩 / Unity 부팅
   (c) 로딩 화면 표시 / 플레이 가능

   Decompression Fallback OFF)의 목표를 웜 3초 달성이 아니라
   콜드 캐시 첫 로드 개선으로 재설정한다. 작업 내용 동일, 측정 대상만 변경.
